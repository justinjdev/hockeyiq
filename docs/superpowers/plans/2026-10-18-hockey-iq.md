# Hockey IQ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static SvelteKit study tool that steps through hockey plays on an SVG rink with per-position coaching notes, two quiz modes, system comparisons, fundamentals lessons, and a full v1 content library.

**Architecture:** All content is typed TypeScript data (plays, lessons, comparisons, glossary) validated by a pure `validate` module that runs as a Vitest suite over the whole library. Pure logic (interpolation, region hit-testing, progress) lives in plain `.ts` modules with unit tests; Svelte components only render. Every route is prerendered from the content registry; a dev-only editor route helps author coordinates.

**Tech Stack:** SvelteKit 3.1 (Svelte 5.57, runes), TypeScript, `@sveltejs/adapter-static` 4, Vitest 5, Playwright 1.64. Google Fonts (Teko, Atkinson Hyperlegible) via `<link>` in `app.html`. No other runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-18-hockey-iq-design.md`

## Global Constraints

- SvelteKit + Svelte 5 runes, TypeScript strict, `adapter-static`, no backend, no accounts.
- Rink coordinates in feet: `x` 0..200, `y` 0..85, origin top-left (SVG space). Our team always attacks to the right; our goal line is `x = 11`, theirs `x = 189`. Blue lines at `x = 75` and `x = 125`, red line `x = 100`. Facing right, a player's right side is larger `y` (so RW/RD live on the bottom half).
- Every step defines positions for every slot and every opponent, plus the puck.
- Notes for each of our slots on every step: `where`, `read`, `why`. Opponents never get notes.
- Every play cites at least one real, recognizable coaching source (USA Hockey, Hockey Canada, published coaching books or sites, well-documented pro systems). Never invent a URL; if a source has no stable URL, omit `url`.
- Jargon in any note/lesson text is wrapped as `[[term-id]]` or `[[term-id|display text]]` and must exist in the glossary.
- Layout: rink + side panel on desktop (>= 900px), panel stacks below the rink on phone. Minimum supported width 360px, no horizontal page scroll.
- Visual tokens (CSS variables on `:root`): `--arena #0d1319`, `--panel #15202b`, `--panel-2 #1e2a36`, `--ice #eef4f8`, `--goal-light #f5b82e`, `--us #2b6cb0`, `--them #e04848`, `--line-red #c8323c`, `--line-blue #2f63c6`, `--text #dde6ee`, `--muted #8fa1b3`. Display font Teko, body font Atkinson Hyperlegible. Highlight ring and key cues use `--goal-light`.
- localStorage access wrapped in try/catch; the app works with storage unavailable.
- Dev editor route is unreachable in production builds.
- Commit after every task, on branch `feat/hockey-iq`. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Deep link to a step or slot that doesn't exist** (`?step=99`, `?as=nope`): clamp step to range and fall back to the first slot, never crash or blank the rink. Test in Task 5 (`parseStudyParams`).
2. **localStorage throws or holds garbage** (private mode, old schema, hand-edited JSON): progress reads return empty and writes are no-ops; quizzes still work. Test in Task 4.
3. **Drag quiz dropped outside the ice or on the boards' rounded corners**: clamp the dropped point inside the rink outline before scoring, and score it as incorrect, not an error. Test in Task 2 (`clampToRink`).
4. **Phone width with long notes**: panel stacks, rink keeps aspect ratio, nothing overflows horizontally at 360px. Test in Task 9 (Playwright at 360x740).
5. **Rapid step changes mid-animation** (spamming next/prev or arrow keys): the rink ends on the final requested step with correct positions, no stuck interpolation. Test in Task 3 (`positionsAt` at t=0/1 for any pair) and Task 9 (Playwright: press ArrowRight 5x fast, assert final step label and RW position).

- Produces (`glossary.ts`): `export const glossary: Term[]` with at least: `f1, f2, f3, strong-side, weak-side, gap, pinch, rim, chip, cycle, net-front, point, half-wall, bumper, slot, high-slot, low-slot, hash-marks, breakout, regroup, forecheck, backcheck, neutral-zone, d-to-d, reverse, wheel, stretch-pass, tag-up, offside, icing, screen, tip, one-timer, seam, shooting-lane, passing-lane, box, diamond, wedge, umbrella, overload, collapse, man-to-man, zone-coverage, support, triangle, shoulder-check, weak-side-d, puck-side`.

Validator rules (each produces one `Issue` with a `where` like `play:bo-standard/step:2/slot:rw`):
1. Unique ids (plays, lessons, slots within play, opponents within play; slot and opponent ids don't collide).
2. `slots.length` is 5 for 5v5 and 5v4, 4 for 4v5; `opponents.length` is 5 for 5v5 and 4v5, 4 for 5v4.
3. `steps.length` between 2 and 8.
4. Every step: `positions` has exactly every slot and opponent id; every position and the puck pass `isOnIce` (Task 2; until then, bounds 0..200 / 0..85); `puckCarrier`, string `Arrow.from`, string `Read.at` reference a known id; `notes` has every slot with non-empty `where`/`read`/`why`.
5. Quizzes: keys are slot ids; drag quiz on step 0 requires `start`; decision quiz has 2 to 4 options with exactly one `correct`; ellipse `rx, ry > 0`; polygon has >= 3 points.
6. Coverage: play has >= 1 drag and >= 1 decision quiz, and every slot has >= 1 quiz of either kind.
7. `sources.length >= 1`, each with non-empty `title` and `publisher`; `url` if present starts with `https://`.
8. `keyConcepts` reference existing lessons; lesson `examplePlays` reference existing plays.
9. Every `[[term]]` in notes, captions, quiz text, summaries, variations, lesson bodies and comparison text exists in glossary.
10. Comparison: `a` and `b` exist, same `category`; both plays' ordered distinct `phase` lists are non-empty and equal; every step in both plays has a `phase`.
